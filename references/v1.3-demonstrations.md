# Demostraciones integrales v1.3

## Negocio nuevo: tienda local

1. **QUESTION, capas 1–3:** en 15 preguntas se identifican cliente local, venta por catálogo, pago confirmado, preparación y reparto; puntuaciones esenciales ≥3. El agente entrega los tres informes y recomienda cerrar. Usuario confirma.
2. **DELETE:** propone retirar el registro obligatorio y el doble ingreso de dirección; mantiene confirmación de pago y consentimiento. Usuario aprueba retirar el registro.
3. **SIMPLIFY:** antes: cuenta → carrito → formulario → reingreso → revisión; después: carrito → datos de entrega → pago → confirmación. Usuario confirma.
4. **ACCELERATE:** baseline pendiente; se instrumentan tiempos pago-confirmado y listo-para-reparto. Se detecta espera manual de copia de datos.
5. **AUTOMATE:** candidato: crear una única orden de despacho desde webhook verificado e idempotente. Action Gate ofrece DESIGN/BUILD/PILOT/HANDOFF. Usuario elige DESIGN; se completa `assets/automation-blueprint.md` con duplicados, reintentos, cola manual y rollback. No se afirma despliegue.

## Sistema existente

El agente inspecciona rutas autorizadas y encuentra dos formularios, pero etiqueta uso como no verificado. El dueño confirma que uno es legado. La propuesta `DELETE + PROPOSED` pasa a `APPROVED`; eso no autoriza borrar código. Tras confirmar el gate, se simplifica la ruta y se prepara un BUILD con tests, sin producción.

## Recuperación extensa (VOLTRIVA hipotético)

Se carga una sesión con 100 preguntas, etapa SIMPLIFY, 18 `APPROVED`, 3 `REJECTED` y 4 `NEEDS_EVIDENCE`. El agente conserva todo, agrega los campos v1.3 ausentes y continúa desde SIMPLIFY. No reabre QUESTION ni reactiva rechazadas. Al llegar a AUTOMATE, un proceso inestable queda `VALIDATE_FIRST`; otro repetitivo y estable recibe HANDOFF porque no existe acceso técnico.
